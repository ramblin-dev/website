# reference/

Summaries of science-backed sources relevant to ramblin.dev — UX research, web-design studies, conversion/engagement findings, and similar. Each file captures findings and citations from peer-reviewed work (typically gathered via Consensus) so the design decisions in `design-backlog.md` and the site itself rest on something more durable than vibes.

**Not shipped with the site.** This folder sits outside `content/`, so Pelican skips it at build time. It exists to inform decisions, not to publish.

## Conventions

- One file per topic (e.g. `cta-placement-research.md`).
- Keep notes **generalizable** — findings, synthesized rules of thumb, and citations only. Don't pre-mix project-specific recommendations into the reference file; those belong in `design-backlog.md` or the implementing page itself. This keeps the notes reusable and lets the source thinking be revisited cleanly.
- Cite papers inline with numbered references and list them at the bottom, hyperlinked to their source URL (the Consensus output already follows this convention — preserve it).
- Prefer peer-reviewed sources. If a non-peer-reviewed source is included, label it as such.
